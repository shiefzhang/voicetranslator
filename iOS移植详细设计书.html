VoiceTranslator iOS 移植详细设计书

离线连续语音翻译 App · Android 0.2.2 对齐方案

文档版本：1.0基线版本：0.2.2 / versionCode 5目标：iOS 15+ · arm64

1. 设计目标与范围

将现有 Android 原生离线语音翻译能力迁移到 iOS，保持用户可见行为、模型包校验、翻译方向限制和数据隐私策略一致。首期只实现前台连续录音、停顿自动分句、离线 ASR、离线 LLM 翻译、双页文本展示和模型导入，不承诺后台或锁屏持续录音。

核心原则：音频与对话文本默认只存在内存；模型包来自用户本地文件；所有导入文件先校验再激活；翻译模型与 ASR 模型独立替换。

3.2 方向限制

主语言始终是 ASR 支持的中、日、韩、英之一。法语、德语、俄语只能作为翻译目标语言。目标语言属于 fr/de/ru 时，左侧反向翻译页不可用，底部导航最左显示“反向不可用”，中间显示“译成法语/德语/俄语”。

reverseAvailable = target ∈ {zh, ja, ko, en}
if !reverseAvailable: page[0].enabled = false; page[0].label = "反向不可用"

3.3 状态与清理

录音或翻译处理中禁止切换语言；切换语言前若存在文本，提示复制并清空或直接清空。停止录音后继续处理已进入队列的句子，完成后回到可开始状态。

5. 模型包与导入设计

5.1 manifest 约束

schemaVersion=1；kind 为 asr 或 translation；语言声明仍为 zh/ja/ko/en 四语。fr/de/ru 是翻译运行时目标，不要求 ASR 清单增加。必需文件分别为 ASR 的 model.int8.onnx、tokens.txt、silero_vad.onnx，翻译的 model.gguf。必须有 licenses/ 文件。

5.2 导入流程

FileImporter
复制到临时目录
ZIP64 + manifest 校验
原子激活

所有路径必须是相对安全路径；拒绝目录穿越、重复文件、未声明文件、超 3GB、文件大小或 SHA-256 不匹配。校验失败不得修改当前已激活模型。导入成功后写入 UserDefaults 的绝对路径，并删除同 kind 的旧包。

关键兼容性：TranslateGemma Q4 包约 2.49GB，普通 ZIP 的中央目录偏移超过 2GB 时 Android 会出现 invalid cen header (bad signature)。打包器必须强制 ZIP64；iOS 解包器也必须支持 ZIP64。

5.3 iOS 存储

下载/导入临时文件放 Library/Caches/ModelImports；激活包放 Application Support/Models/<id-uuid>。不要依赖用户可见 Documents 保存运行模型；若支持“文件 App”导入，使用 security-scoped URL 复制内容后立即停止访问。

6. 翻译引擎移植

将现有 translator.cpp 编译为 Objective-C++ 静态库或 XCFramework，Swift 侧通过 TranslationBridge 暴露 load/translate/cancel/close。保持单模型、单 context、串行推理约束。

load(modelPath, engine)
translate(source, fromCode, toCode, onPartial) -> Result
cancel()
close()

Qwen 使用 few-shot 示例和严格目标语种规则；TranslateGemma 使用专用 role prompt。语言映射必须包含 Chinese/Japanese/Korean/English/French/German/Russian。输出检查：中文需包含 CJK 且无假名/韩文；日语需含假名；韩语需含 Hangul；法德英允许拉丁脚本；俄语要求 Cyrillic。检查失败时 Qwen 重试一次，Gemma 直接返回可读错误。

8. 错误处理与安全

错误用户提示恢复
无麦克风权限请在系统设置开启麦克风权限跳转设置
模型清单/校验失败模型包损坏或不兼容保留旧模型，重新选择文件
ZIP 中央目录错误模型包格式不兼容，请重新获取 ZIP64 包不激活临时包
内存不足/句子过长请缩短句子或更换 Q3 模型清理 context 当前句
翻译语种错误模型未返回目标语种，请重试或更换模型Qwen 自动重试一次

不记录原始音频、模型输入输出或用户文本到日志；生产日志只保留错误类别、耗时和模型 ID，不记录句子内容。模型包 SHA-256 是完整性校验，不等价于签名认证。

10. 迁移阶段与交付物

  1. Phase 1：建立 SwiftUI 壳、UserDefaults、模型导入与 ZIP64/manifest 校验。
  2. Phase 2：接入 AVAudioEngine、Segmenter、SenseVoice/Silero，完成前台录音闭环。
  3. Phase 3：接入 llama.cpp，先 Qwen，再 TranslateGemma；完成 prompt 和脚本检查。
  4. Phase 4：实现双页 UI、导航限制、分享、主题、无障碍。
  5. Phase 5：真机性能、稳定性、许可、签名和 TestFlight 验收。

交付物包括：iOS Xcode 工程、SwiftUI 页面、Objective-C++ 推理桥、模型包校验库、单元/UI 测试、第三方许可清单、模型导入说明和 TestFlight 构建脚本。
