1 · 为什么两端策略不同

关键前提：`.vtmodel` 是 STORED（无压缩）zip。gguf / onnx 本身已经压缩过， 再 deflate 一点收益都没有 —— 882 MB 的包压完还是 882 MB。这一条决定了两端的选择。

做法bundle / APK 内设备上再解一份合计结论
放 zip + 首启解压到沙盒1.1 GB1.1 GB2.2 GB iOS 不选
放解包后的目录，只读直接用1.1 GB01.1 GB iOS 选它
assets 放 zip，首启解包1.1 GB1.1 GB2.2 GB Android 选它
assets 放解包后的文件，首启拷贝1.1 GB1.1 GB2.2 GB 一样，不选

iOS —— 可以省掉一半

iOS 的 bundle 里就是**真实文件**，而 sherpa-onnx / llama.cpp 只需要读模型， 只读的 bundle 路径刚好够用 —— 运行期不往模型目录写任何东西。 所以直接把解包后的目录放进 bundle，省掉设备上那份副本。

Android —— 省不掉，就选规则不分叉的那条

assets 不是普通文件，只能通过 AssetManager 流式读，而 native 层要的是真实路径， 所以无论如何都得在 filesDir 解一份。两种做法占用完全一样，那就选 复用现有校验流程的：assets 放 zip，运行期走和用户手动导入完全相同的解包路径， 逐个文件核对 SHA-256。

两端必须内置同一个包。v0.2.4 的语种契约就是这么漂移的（一端从 4 语扩到 5 语，另一端没跟上）。 所以候选筛选只写一份 —— scripts/bundle-models.py，--target 只决定产物写到哪里。

3 · 顺手修掉的两个 bug

这两个都不是需求的一部分，是通读代码时撞出来的。第二个尤其要紧 —— 它会让内置包功能在它唯一的使用场景里 100% 失败。

3.1 onActivityResult 整个是缺失的 存量 bug

MainActivity 里 startActivityForResult(in, 60) 有， 但全项目检索 onActivityResult —— 0 命中。 也就是说设置页「选择模型包」能打开文件选择器，选完文件什么都不会发生， 导入功能根本没接上。这跟内置包无关，是一直躺在那儿的。

3.2 unpack() 不建 models/ 目录 新引入

installBundled() → unpack() 直接进来 → staging.mkdir() → 返回 false → 抛异常
环节用户导入路径内置包路径
入口install()installBundled()
建 models/ 目录有 :118 base.mkdirs()没有
建 staging 目录staging.mkdir()staging.mkdir()
结果正常干净安装时抛「无法创建解包目录」
为什么这个 bug 一定会被撞到：File.mkdir() 不创建父目录。 内置包的唯一使用场景就是「干净安装、用户从没导入过任何包」—— 这时 noBackupFilesDir/models 并不存在，staging.mkdir() 返回 false。 异常又被 prepareBundled 的 catch 吞成一句 toast： 「内置模型包准备失败：无法创建解包目录」。用户看到的就是"每次都提示准备失败"。

修法：把 base.mkdirs() 放进唯一漏斗 unpack()，而不是依赖调用方记得建。 

// app/src/main/java/com/vt/voicetranslator/ModelPackages.java:95
- File base = new File(c.getNoBackupFilesDir(), "models"), staging = new File(base, "stage-" + UUID.randomUUID());
+ File base = new File(c.getNoBackupFilesDir(), "models");
+ // 必须在这里建，而不是靠调用方：installBundled() 是直接进来的，
+ // 干净安装时 models/ 还不存在，而 staging.mkdir() 不建父目录会直接失败。
+ if (!base.isDirectory() && !base.mkdirs()) throw new IOException("无法创建模型目录");
+ File staging = new File(base, "stage-" + UUID.randomUUID());

6 · 怎么用

构建（改了模型包之后）

# 看每个 kind 会选中哪个包，不写盘
python3 scripts/bundle-models.py --list

# 写入两端工程（每个 kind 取体积最小的；--pick translation=<id> 可指定）
python3 scripts/bundle-models.py --target both

# iOS 必须再跑一次工程生成器，把 BundledModels 注册进去
python3 scripts/gen-ios-project.py

# 然后照常构建
bash scripts/build-ios.sh --device
./gradlew :app:assembleDebug          # ← 这一步还没人跑过

改模型包的注意事项

  • iOS 改了模型包必须重跑 gen-ios-project.py。 目录存在但工程没引用是静默失败 —— Xcode 什么都不说，装到设备才发现包不在。 build-ios.sh 会直接报错拦下这种情况。
  • 两端必须内置同一个包，所以候选筛选只写一份，别绕过脚本手工拷。
  • 两处产物都是生成物，已在 .gitignore，不要提交 1.1 GB 的模型进仓库。
