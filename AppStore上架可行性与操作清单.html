最该先看的一条：审核可用性缺口。 App 内置的只有 asr（转写） 与 opus（专用翻译，只覆盖 zh↔en、zh↔ja 四向）；通用翻译模型（Qwen 1.04 GiB）刻意没有内置，要用户在设置页手动导入。 后果：审核员如果试 英→日 / 日→英 / 韩 / 粤，界面会给出「先去导入通用模型包」——在 Apple 眼里这属于 Guideline 2.1 App Completeness（功能不完整）。这是本项目最可能被拒的一条，且与代码质量无关。
第二条：隐私清单缺失。自 2024-05-01 起，用到 required reason API 却不在隐私清单里声明理由的构建，App Store Connect 直接不接受上传。本项目的 UserDefaults.standard 就在这个清单里（ios/VoiceTranslator/Models/ModelPackages.swift:125,255,501,522）。

三、必改项 ①：补 PrivacyInfo.xcprivacy（阻塞级）

本项目实际命中的 required reason API 只有一类：UserDefaults。代码里没有 statfs / 磁盘空间探测，也没有文件时间戳读取，所以清单可以写得很干净。

1. 新建 ios/PrivacyInfo.xcprivacy

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
	<key>NSPrivacyTracking</key>
	<false/>
	<key>NSPrivacyTrackingDomains</key>
	<array/>
	<key>NSPrivacyCollectedDataTypes</key>
	<array/>
	<key>NSPrivacyAccessedAPITypes</key>
	<array>
		<dict>
			<key>NSPrivacyAccessedAPIType</key>
			<string>NSPrivacyAccessedAPICategoryUserDefaults</string>
			<key>NSPrivacyAccessedAPITypeReasons</key>
			<array>
				<string>CA92.1</string>
			</array>
		</dict>
	</array>
</dict>
</plist>
  • CA92.1 = 仅访问本 App 自身的 user defaults（用于记住引擎档位、朗读模式、导入的包名）。
  • 三项「空」声明是刻意的：本 App 不跟踪、不收集数据、不联网。隐私标签与清单因此可以完全对齐 —— 审核时这是加分项。
⚠️ 关键：不能只在 Xcode 里拖进去。 本工程的 project.pbxproj 是 scripts/gen-ios-project.py 整体生成的（枚举式，非 synchronized folder）。手动加的文件会在下次重跑生成脚本时静默消失，而构建照常成功 —— 表现为「本地打包没问题，上传却报缺隐私清单」。 所以必须同时改生成脚本：把 PrivacyInfo.xcprivacy 作为资源文件引用写进 PBXResourcesBuildPhase（与 Info.plist / Assets.xcassets / BundledModels 同样的处理路径，见 gen-ios-project.py:190-265）。

2. 验证方式（别只看文件存在）

# 判据：产物 bundle 根目录下真的有这个文件，且是这一轮编出来的
python3 scripts/build-ios.sh --release

四、必改项 ②：补加密出口合规声明

App 没有任何自研加密算法，只有系统 TLS（实际上连网络请求都没有），属于豁免情形。加这个键之后，每次上传不再被弹窗追问。

改 ios/Info.plist（唯一真源，改完重跑生成脚本）

<key>ITSAppUsesNonExemptEncryption</key>
<false/>

另建议顺手把版本改成首发语义：CFBundleShortVersionString 从 0.2.15 → 1.0.0、CFBundleVersion → 1。App Store 上架后 CFBundleVersion 只能单调递增，首发用 18 会白白吃掉 17 个号段。

三个可选方案

方案做法安装包拒审风险代价
A. 补内置通用模型
推荐		 把 Q4_K_M 加入 BUNDLED 表，一次配齐 ≈ 1.95 GiB 消掉 包体翻倍；需走 Wi-Fi 下载；首启不再需要手动导入
B. 首启引导 + 审核备注 保持 912 MiB，加一段首启引导页 + 审核备注说明 912 MiB 仍有残险 零成本，但取决于审核员是否读懂备注；最坏情况来回一两轮
C. 扩 OPUS 覆盖面 给 en↔ja 等补官方 OPUS 单包 +数百 MiB 部分消掉 韩/粤仍缺；opus-mt-ja-en 等需重新打包验收
我的建议：先 B，看审核结果再决定要不要上 A。 理由：A 会让安装包接近 2 GiB，下载转化率断崖式下跌，为一个可能根本不会触发的审核场景付这个代价不划算。 B 的成本只是「一段引导 + 一段英文备注」，且即使被拒，拒审意见会明确指向缺功能，那时再上 A 也是一次有据可依的改动。

审核备注模板（App Review Information → Notes）

This app performs 100% on-device speech translation. There is no network
access at all — no account, no login, no server.

Out of the box, Chinese<->English and Chinese<->Japanese work immediately,
because the ASR model and the compact OPUS-MT translation model are bundled
inside the app.

Other language pairs (e.g. English<->Japanese, Korean, Cantonese) use a
larger general-purpose translation model, which is intentionally NOT bundled

To test those pairs:
1. Tap the gear icon (Settings) -> "Model packages".
2. The app shows exactly which package is missing and how to import it.

If you need a ready-to-import package for review, please contact us at

Note: the app will never crash or hang when a model is missing — it always
shows a clear, actionable message pointing to the settings screen.

七、体积策略与下载体验

912 MiB当前内置asr 229 MiB + opus 683 MiB
4 GB未压缩上限余量充足，不是约束
1.04 GiB通用模型未内置，用户自行导入
>200 MB必然超蜂窝阈值默认只能走 Wi-Fi 下载
真正影响转化的是蜂窝下载限制，不是 4 GB 上限。 App 安装体积 912 MiB 远超蜂窝网络默认下载阈值，用户在没连 Wi-Fi 时会看到「需要 Wi-Fi 才能下载」。 可在 App Store Connect 里申请提高该上限，但 Apple 不保证批准，且与「这是个离线小工具」的定位不符。 方案 A（补内置通用模型）会把这个问题放大到 ≈1.95 GiB，这是我建议缓一步的主要原因。

另：Apple 官方文档提到可以用 Apple-Hosted Background Assets 托管大体积资源，但该能力要求 iOS 16+，与本项目 iOS 15.0 的部署目标冲突 —— 走这条路等于放弃 iPad mini 4 这台目标机。不建议。
